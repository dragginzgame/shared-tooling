# Shared Tooling 0.4 changelog

[Release index](../../CHANGELOG.md). Historical notes below retain their original
versions, dates and content; current contracts are documented in the main guides.

## [0.4.2]

### Changed

- Establish Shared Tooling as the owner of shared executable storage. Consumers
  must follow its canonical installers rather than add independent stores or
  bespoke `.tools` installation logic. The intended per-user store will reuse
  verified binaries across checkouts while preserving each repository's pins.
  This release adds the policy; installers still use `.tools` pending
  [#120](https://github.com/dragginzgame/shared-tooling/issues/120).

## [0.4.1]

### Changed

- Classify releases by their own consumer impact: adopting a breaking Shared
  Tooling update does not require a library minor release when its published
  contract remains unchanged. Contributor-only setup changes use patch notes;
  public API, runtime and supported consumer build changes still need review.
  ([#118](https://github.com/dragginzgame/shared-tooling/issues/118))

### Fixed

- Align the canonical version with 0.4.0 so snapshot exports identify the
  delivered tooling release correctly.
  ([#119](https://github.com/dragginzgame/shared-tooling/issues/119))

## [0.4.0]

### Breaking

- Install common Rust tools through the same verified, versioned slots as
  consumer-selected Cargo executables. Refresh shared callers, change Rust PATH
  entries to `.tools/rust/common/bin`, and rerun setup and offline checks.
  Partial upgrades retain the previous complete set; older installations and
  failed evidence remain available. See the
  [adoption instructions](../../docs/consuming-snapshots.md#rust-installation-adoption-in-040).
  ([#118](https://github.com/dragginzgame/shared-tooling/issues/118))

### Added

- Preview snapshot refreshes without changing the consumer, showing file changes
  and all required companion additions before an explicit refresh.
  ([#118](https://github.com/dragginzgame/shared-tooling/issues/118))
