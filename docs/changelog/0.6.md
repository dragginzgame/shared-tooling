# Shared Tooling 0.6 changelog

[Release index](../../CHANGELOG.md). Historical notes below retain their original
versions, dates and content; current contracts are documented in the main guides.

## [0.6.6]

### Fixed

- Select `cargo-sort-derives` 0.14.1 to preserve literal `$crate` paths during
  direct and conditional derive sorting. Real-hook coverage now checks
  unprotected exported macros and compiles them from a separate crate.
  Consumers adopting the pin must explicitly prepare the new tool with Rust
  1.88 or newer and qualify their macros before removing workaround markers;
  library MSRVs are unchanged.
  ([#113](https://github.com/dragginzgame/shared-tooling/issues/113))

## [0.6.5]

### Fixed

- Admit prepared Rust-tool receipts during staged formatting while checking the
  exported pins and compiler. Missing or mismatched selections still refuse
  without installation or changes to the commit payload.
  ([#130](https://github.com/dragginzgame/shared-tooling/issues/130))
- Let validation gates declare prepared inputs and stop subsequent stages when
  those inputs change or cannot be read. Nested gates retain the same checkpoint;
  failures preserve logs, input identities and the original target status.
  ([#129](https://github.com/dragginzgame/shared-tooling/issues/129))
- Document and qualify Make fixtures that substitute command effects without
  replacing shared recipes, avoiding repeated recipe-override warnings while
  retaining ordering and failure checks. Consumer fixture adoption remains local.
  ([#128](https://github.com/dragginzgame/shared-tooling/issues/128))

## [0.6.4]

### Added

- Provide one shared Make entrypoint for common setup, offline checks,
  formatting, hook installation and releases. Custom workspace and frontend
  formatters retain their local policy through paired command inputs, with
  shared failure handling and concise output. See the
  [consumer Make interface](../../docs/make-interface.md) for adoption.
  ([#130](https://github.com/dragginzgame/shared-tooling/issues/130))

## [0.6.3]

### Fixed

- Restart interrupted direct preparation automatically after its metadata
  disposition is committed in a clean descendant checkout. Standard release
  targets preserve the old plan, select the requested increment from current
  metadata and run fresh validation instead of blocking on the old source.
  ([#126](https://github.com/dragginzgame/shared-tooling/issues/126))

## [0.6.2]

### Fixed

- Explain source conflicts in interrupted releases with exact plan and commit
  identities, and document guarded recovery when consumer evidence proves
  preparation never began.
  ([#126](https://github.com/dragginzgame/shared-tooling/issues/126))
- Distinguish Audit and Machete execution in shared-tool adoption guidance,
  including Machete's inherited Cargo launcher context and failure propagation.
  ([#123](https://github.com/dragginzgame/shared-tooling/issues/123))

## [0.6.1]

### Fixed

- Stop Cargo setup immediately on lock, validation or activation failures, with
  the original failure status and retained evidence. Failed setup no longer
  reports success or attempts activation without its locks.
  ([#120](https://github.com/dragginzgame/shared-tooling/issues/120))
- Compare build counts numerically so Cargo installation fixtures accept padded
  macOS output; exercise padded counts on every host.
  ([#124](https://github.com/dragginzgame/shared-tooling/issues/124))
- Resolve tag-maintenance fixture paths consistently with the helper when
  temporary directories use symlink aliases, including macOS temporary roots.
  ([#127](https://github.com/dragginzgame/shared-tooling/issues/127))

## [0.6.0]

### Breaking

- Share Cargo-built tools across checkouts using a standard tool-build environment
  and exact compiler, native environment, package and packaged-lock identities.
  Refresh installers and evidence collection, then explicitly reinstall and check
  common and selected Cargo tools. Application build settings remain local;
  previous installations and failed build evidence are preserved. See the
  [adoption instructions](../../docs/consuming-snapshots.md#shared-cargo-storage-adoption-in-060).
  ([#120](https://github.com/dragginzgame/shared-tooling/issues/120))

### Fixed

- Retain and upload safe local failure evidence when shared-store admission fails,
  with explicit incomplete-collection diagnostics rather than losing the archive.
  ([#121](https://github.com/dragginzgame/shared-tooling/issues/121))
- Report the exact shared installation lock when offline tool checks refuse
  another checkout's active installation.
  ([#120](https://github.com/dragginzgame/shared-tooling/issues/120))
- Allow snapshot distribution checks to omit optional companion-pair cases for
  unselected entrypoints, without requiring consumers to import fleet reporters.
  ([#122](https://github.com/dragginzgame/shared-tooling/issues/122))

### Changed

- Document audit/machete extension adoption through the shared Cargo installer,
  including quiet verified reuse and execution through the selected path.
  ([#123](https://github.com/dragginzgame/shared-tooling/issues/123))
- Rank the sibling GitHub dashboard by open issue count and colour repository
  rows by their current backlog. Remove the lifetime percentage fixed; retain
  closed/total counts, daily activity and pull-request totals.
